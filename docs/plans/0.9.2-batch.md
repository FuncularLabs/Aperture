## What the code says (premise checks)

- **Quick view plays a video as soon as it's shown** (`VideoPlayback.Show` calls `Open` then `Play`). The still stays
  until the player has opened, then the video's own frame shows (`IsReady`).
- **No position or length anywhere**: `IVideoPlayer` has neither; `MediaElementPlayer` doesn't set `ScrubbingEnabled`,
  so a seek while paused wouldn't show its frame.
- **Online-only files are already detected and counted** (0.9.1): `FileScanner` reads the attributes with the size and
  time (`CloudFiles.IsOnlineOnly`: Offline, RECALL_ON_OPEN, RECALL_ON_DATA_ACCESS); `Indexer.IndexRoot` counts those it
  will read (new, changed, or without fresh thumbnails) as `IndexProgress.OnlineOnly`, and the indexing line says they
  are downloaded as they're indexed. Nothing asks; every one is read in scan order.
- **What runs an index**: the startup reconcile of every folder, Add folder / a drop / New library's folder, the
  folder's Include subfolders toggle, Include videos (every folder), Resume, and the watcher (debounced, on its timer
  thread, then on the UI thread). Runs of different folders, and of the same folder, can overlap.
- **The rename highlight (carried as OOR-1)**: `OnRootAliasChanged` calls `BuildTree()`, which rebuilds every node, and
  never re-selects the current location; `MoveRoot`, `OnFolderShownChanged` and the refresh all call `SelectPath` after
  `BuildTree`. (Revision 2: there is no breadcrumb on screen — `BuildBreadcrumb` has no caller and `Breadcrumb` is bound
  nowhere — and the title bar shows the folder's path, not its name, so a rename changes nothing else.)
- **Cut and Copy act on one tile**: `PutFileOnClipboard(TileVm)` puts that tile's file alone on the clipboard; the menu
  passes the right-clicked tile and Ctrl+C / Ctrl+X pass `SelectedTile`. The selection is known (`_selectedTiles`,
  pushed from the grid), and a tile drag already uses it (`OnGridPreviewLeftDown`: the selection when the pressed tile
  is in it, else that tile).
- **Tags and notes are keyed by the file's full path** (`annotations.path`; `LibraryRow.FullPath` =
  `Path.Combine(root.Path, relPath)`). A file moved in Explorer loses them today. `AnnotationStore` has no move.
- **Another library's folders** are only in that library's own `aperture.db` (`roots.path`); the registry has names,
  folders and counts, not roots. Only the active library is open (single instance since 0.8.9's Option B).
- **Quick view's menu** passes `PreviewTile` (= `SelectedTile`) to Copy and Cut; a selection stays selected while quick
  view is open.
- **A run's write transaction** spans each batch of 200 files (`Indexer.IndexRoot`), which on cloud files can take
  minutes; another write waits `busy_timeout` (5 s) and then fails. Tag counts are counted from the rows
  (`GetTagCounts`), and `Save` bumps a tag's recency.
- **After `MediaEnded`** a Manual `MediaElement` is reported to stay in its playing state; `OnEnded` doesn't pause it.

## Acceptance criteria

### Quick view video (items 1–3)

- **V9** Quick view opens a video paused — moving to one too, and reopening on one. It plays only on the play button,
  `Space`, or a click on the video. Once it has opened, it shows no "Loading video…" line, and the play button shows
  "play". The still frame shows until the video is played or moved along (see V10); then the video's own frame shows.
  A video that can't be played keeps its still and its line, as in 0.9.1.
- **V10** A playable video shows a seek bar and a time, "elapsed / length" (`m:ss`, or `h:mm:ss` when the length is an
  hour or more). Until it has opened the bar is disabled and the time reads `0:00 / –:––`. Clicking or dragging the bar
  moves the video there, playing or paused, before it has ever been played too (rev 4, R2-1); a paused video then shows
  the frame there and stays there, and play goes on from there. While it plays, the bar and the
  time follow it (a few times a second); while the bar is dragged they follow the drag, not the player. At the end the
  bar is at the end; moving it back and pressing play plays from there (not from the start). A length the player can't
  tell leaves the bar disabled and the time `m:ss` alone.
- **V11** Quick view's hint line for a playable video still says "Space or click to play or pause · Esc to close · ← →
  to move · Enter to open"; the seek bar and time take no keys (← → still move between items).
- **V12** (rev 2; rev 3) A video that reaches its end stops there; moving the bar back leaves it paused where it was put,
  and play goes on from there (a seek while not playing pauses the player once the seek has gone through: round 1,
  A-F1). With no still (one the shell couldn't make), the whole area is the video until its frame shows.

### Online-only files (item 4)

- **C1** A run that would read online-only files (those 0.9.1 counts: new, changed, or with stale thumbnails) asks
  first, once, before it reads any file and before its first indexing report: it names the folder and how many, and
  offers **Skip them**, **Index in the background**, **Index now** (Skip the default), and **Remember for this
  folder** (unticked), and says skipped files stay out of Aperture until another choice from the folder's menu. A run that reads none never asks. While the question waits, the run holds no thread (rev 2: the run
  awaits the answer; nothing blocks the thread pool, however many folders ask at once). Answered after more than 2 s,
  the run counts the files again (rev 3: the folder may have changed, unwatched).
- **C2** Skip: none of them is read. One not yet in the library stays out; one already in it keeps its row as it was
  (never pruned for being skipped). Every other file is indexed as usual. The indexing line doesn't count them, and the
  run's total leaves them out (its bar reaches the end). Accepted: a tile whose cached thumbnail was evicted still
  makes it again from the file, as before.
- **C3** In the background: every other file is indexed first, in its usual order; then the online-only ones. The
  indexing line says they're downloaded after the rest — when every run that downloads any says so; otherwise the 0.9.1
  line.
- **C4** Now: as 0.9.1 — read in order with the rest; the line says each is downloaded as it's indexed.
- **C5** An answer holds for that folder while the library stays open (the view model's; a switch away and back, or a
  restart, asks again): a later run of it (the watcher, Resume, a toggle) doesn't ask again. Ticking Remember keeps it
  with the library (its settings), so it holds after a restart. Closing the dialog (`Esc`, ✕) is Skip, for the
  session, not kept. All of it is read and written on the UI thread.
- **C6** A folder's right-click menu has **Online-only files** ▸ **Ask each time**, **Skip**, **Index in the
  background**, **Index now**, the one in force checked (kept, else the session's, else Ask each time). Choosing one
  keeps it, as Remember does; choosing Ask each time forgets the kept and the session answer and starts nothing. A
  choice that reads files the last answer skipped (Skip → background or now) re-indexes the folder, unless it's paused
  (its Resume reads them; rev 3).
- **C7** One question at a time: two folders asking at once get one dialog, then the other. A run that asks while a
  question for the same folder is open waits for it and uses that answer. A question whose folder was removed, paused
  or stopped, or whose library is closing (switch, exit), is given up: no dialog afterwards, nothing read, no hang at
  exit.
- **C8** Removing a folder forgets its kept answer.

### The folder list (item 6)

- **R1** Renaming the folder you're in, or one above it, keeps it selected (highlighted) in the folder list. Renaming
  another folder leaves the current one selected; in Everything nothing is selected. (Revision 3: no breadcrumb is
  shown anywhere, so none is updated.)

### Cut, Copy and Move (items 7, 8)

- **X1** Cut and Copy — the grid's menu and `Ctrl+X` / `Ctrl+C` — put every selected file on the clipboard when the
  tile they act on is part of the selection; a right-click on a tile outside the selection acts on that tile alone.
  Quick view's (and the preview's) Copy and Cut act on the item shown alone, even in a selection; that menu shows no
  key for them. Cut marks them as a
  move (Preferred DropEffect 2), Copy as a copy (5). Files no longer on disk are left out, a file shown twice (nested
  folders) once; when none is left, the clipboard is untouched. Tests use the view model's clipboard seam, never the
  PC's clipboard.
- **M1** A tile's right-click menu in the grid has **Move to…**, acting on the same files as X1 (quick view has none).
  It asks for a folder (the picker starts in the folder shown, when it is one), then moves the files there. While a
  move runs the status bar says so and Move to… is unavailable.
- **M2** A folder this library indexes — inside one of its folders, and, for a folder that doesn't include subfolders,
  that folder itself — takes the files without a question; a hidden subfolder or an unticked folder counts (the files
  leave the view). Any other folder asks first, saying why: it's in library "X" (its tags and notes won't show there),
  or it isn't in any library (they won't show in Aperture). No moves nothing. Other libraries' folders are read off
  the UI thread, read-only, and only when the folder isn't this library's; one whose folders can't be read isn't
  counted as holding it. Accepted: a folder reached by another name (junction, mapped drive, 8.3 name) isn't
  recognised — the cost is a needless question.
- **M3** A move never overwrites: a file whose name is taken in the destination stays where it is; a file already in
  that folder is left as it is; a file that can't be moved (in use, access denied at either end, gone, its destination
  gone) stays. Afterwards, only if any wasn't moved, one message says how many were moved and why the rest weren't.
- **M4** Tags and notes go with each moved file: they're kept under its new path in this library (also when it moves
  out of the library, so they come back if its new folder is added). Whatever is kept under the new path (left by a
  file that was there once) is replaced — cleared, for a file with none. A move never changes a tag's recency or
  count. The tags move in one short write with the file's move: when the library can't be written (a run holds it),
  the file stays, its tags with it, and the message says the library was busy; a file whose move fails keeps its tags
  where they were. A file with no tags, and none kept under its new path, never waits on the library.
- **M5** The grid, the counts and the tags shown follow: the moved files leave their old folder, and appear in the new
  one, with their tags, when this library indexes it. (Rev 3, B-2:) a file moved into a folder of this library takes
  its row with it, in the same write as its tags, so the next run finds it unchanged — nothing read again, an
  online-only one not downloaded, nor left out by Skip; the window reads the rows at once. (Rev 4, R2-2:) a tagged or
  online-only file waits for that write and stays when it can't be had; a local file with no tags tries it briefly and,
  the library busy, moves anyway: the next run reads it again as a new file (accepted). Each affected
  folder that isn't watched is re-indexed; a paused folder is left paused (its resume picks the move up).
- **M6** The move runs off the UI thread, tracked by the library: a switch waits for it, and a switch or exit stops it
  (at most 5 s for exit, as for indexing): a file not yet begun is Stopped, a copy across drives in progress stops and
  is removed (rev 3), never half moved. A tag write that fails once the file has moved is made again; failing again,
  the file is "moved without its tags", and the summary says so.
- **M7** A move across drives copies the file, in chunks on the move's token, to a temporary name in the destination
  (`<name>.aperture-moving`, which no scan picks up), keeping its times, other streams and encryption (`CopyFileEx`)
  and its plain attributes (read-only, hidden, system, archive; not a cloud placeholder's), then renames it and deletes
  the original (a read-only one too); a failure or a stop removes the copy. When the original can't be deleted, the copy is
  removed and the file stays ("in use"). A leftover copy (read-only or not) is replaced. Accepted: a process killed
  mid-copy can leave a `.aperture-moving` file.

## Design

- **Playback.** `Show` opens the player and calls `Pause` (a Manual `MediaElement` opens on Play or Pause), not `Play`.
  `ShowsFrame` (new) = opened and (played or seeked once); the window swaps the still for the player on `ShowsFrame`,
  not `IsReady`. `IVideoPlayer` gains `Position` (get/set) and `Duration` (`TimeSpan?`, from `NaturalDuration`).
  `MediaElementPlayer` sets `ScrubbingEnabled`. `VideoPlayback` gains `PositionSeconds` (set = `Seek`),
  `DurationSeconds`, `CanSeek`, `TimeText` (`MediaTime.Format`), `Tick()` (reads the player's position unless
  scrubbing), `BeginScrub`/`EndScrub`. The window runs a 200 ms `DispatcherTimer` while a video is shown and wires the
  slider's thumb drag to the scrub calls. The slider and time sit on the controls row, not focusable.
- **Online-only.** `Indexer` splits a run into its count (`Prepare`) and its reads (`Execute`). `IndexRoot` (sync)
  takes a synchronous asker (null = Now, as before); `IndexRootAsync` awaits an asynchronous one between the two, so a
  waiting question holds no thread; `LibraryService.IndexRootAsync` runs the async form inside its tracked `Task.Run`.
  Both ask after the count, before the first indexing report and before the connections open, only when the count is
  above 0. Skip takes the files it would download out of the work list (marking them seen); Background puts them last;
  Now leaves the order. `IndexProgress.OnlineOnlyLast` lets the line say "after the rest". The VM's asker hops to the
  UI thread and does everything there: the kept and session answers (`OnlineOnlyChoices`, Core, over the library's
  settings), an async gate so one dialog shows at a time, a re-check after the gate (answers, the folder still there
  and not paused, the library not closing), the dialog (`ShowOnlineOnlyDialog` seam → `OnlineOnlyDialog`), and the
  record of the answer. The run's token cancels the wait (the run then ends; an answer given later is still recorded
  for the folder).
- **Rename.** `OnRootAliasChanged` re-selects the current location after `BuildTree`.
- **Clipboard targets.** One rule, `ActionTargets(tile)`: the selection when the tile is in it, else the tile; distinct
  by path, on disk. The grid's Cut, Copy and Move use it; quick view's and the preview's menu use
  `CopyShownFileCommand` / `CutShownFileCommand` (the tile alone). The clipboard is the `SetClipboard` seam.
- **Move.** VM: targets → picker (`PickMoveDestination`, starting in the folder shown) → `MoveDestination.Classify`
  against this library's folders; only if that isn't this library, `OtherLibraries()` in the background (App:
  `CatalogService.OtherLibraryFolders`: each other library's `aperture.db` opened read-only, unpooled, as
  `LibraryCount` does, reading `roots.path`) → `ConfirmMove` → `LibraryService.MoveFilesAsync` (tracked like an index
  run, so a shutdown waits; stops between files on the token) → `FileMoves.Move` per file:
  1. the destination name must be free (else "name taken"); the same folder is left alone;
  2. across drives, copy to `<name>.aperture-moving` in the destination first;
  3. when the file has tags, or something is kept under its new path, begin a write on the metadata file
     (`BEGIN IMMEDIATE` on its own connection; busy → the copy removed, the file stays, "library busy") and re-key the
     row (delete what's under the new path, then move the file's row there; raw SQL, so recency and counts are as
     they were);
  4. rename (same drive: `File.Move(src, dst, false)`; across: the copy to its name, then delete the original — if that
     fails, the copy is removed);
  5. commit; any failure before it rolls back and cleans up, so the file and its tags stay together.
  Then the VM reloads the tag cache, says what wasn't moved (`ShowMoveSummary`), and re-indexes each affected folder
  of this library that isn't watched and isn't paused.
